# 项目研究原则与长期约束

> 本文件保存跨对话、跨阶段不能丢失的研究方法和边界。它比某次具体技术方案优先级更高。

## 1. 总目标

- 核心目标是为嵌入式秋招建立能够讲清楚、经得住追问的项目体系。
- 不要求把设想中的每一个工业功能都做成实物；重点是问题定义、方案推导、取舍依据、关键实验和调试证据。
- 代码是把方案翻译成 C 语言并验证关键假设的工具，不是项目研究的唯一产物。
- 理论研究可以写入简历，但内部必须知道哪些是实机验证、台架/模拟验证、设计研究。
- 不一次性扩展全部内容，采用有计划、有产出、有验收点的分阶段推进。

## 2. 两个项目必须分开

### 2.1 当前主项目

当前主项目暂定为：**无人值守精密实验环境智能管控与设备运维系统**，优先以光学暗室等精密实验空间作为具体场景。

它研究环境与设备采集、本地控制、工业通信、边缘网关、远程运维、日志诊断和多节点升级，不应为了复用已有知识而与 BMS 过度绑定。

### 2.2 BMS 项目

BMS 是独立项目，已有 BQ76940/BQ76200/BQ34Z100-G1、F103、CAN 和 IAP/OTA 的初步分析。除非用户明确指令，暂不继续展开。

两项目可以共享 FreeRTOS、CAN、Bootloader、Manifest、故障恢复等通用方法，但必须单独说明产品目标和安全策略差异，避免简历中出现两个内容几乎相同的项目。

## 3. 硬件型号不是产品方案的起点

- 简历中的产品硬件不必机械等同于手头的 F103C8T6、F407ZGT6 和 ESP32-S3 N16R8。
- 产品选型应从成本、供货、主频、Flash/SRAM、引脚数量、封装、接口类型/数量、DMA、FPU、低功耗、温度等级、升级空间和安全需求推导。
- 现有开发板是原型验证载体，用于验证架构、流程、协议和调试方法。
- 研究文档必须区分“产品候选型号”和“实验使用板卡”，并说明二者如何映射。
- 选型不是简单比较参数大小，还要形成引脚预算、RAM/Flash 预算、通信带宽预算和成本/BOM 约束。

## 4. 每个项目按四条主线研究

### 4.1 硬件选型

研究主控、通信模块、传感器、存储器、收发器和电源模块为什么这样选，至少回答：

- 需求需要哪些 GPIO、ADC、定时器、DMA、UART、SPI、I²C、CAN、Ethernet？
- Flash、SRAM、任务栈、协议缓冲区和升级镜像需要多少空间？
- 为什么不选更低成本或更高性能的芯片？
- 原型板与产品板有哪些差异？

### 4.2 软件架构

脑中必须有稳定框架：BSP/HAL、设备驱动、服务、协议、业务、平台适配和应用装配。每层需要说明职责、依赖方向、数据所有权和错误传播方式。

### 4.3 软件流程

不用堆完整代码，优先使用任务表、状态机、时序图和伪代码说明：

- `main` 初始化顺序；
- 每个任务负责什么、优先级为什么这样分；
- 中断如何通知任务；
- 队列、事件组、信号量、互斥锁分别用在哪里；
- 数据怎样从驱动流向业务，再流向通信；
- 失败、超时、重启和恢复怎样处理。

### 4.4 知识点与面试题

按四类建立问题库：

1. **芯片：** 内核、主频、时钟树、Flash/SRAM、启动、中断、DMA、低功耗、看门狗；
2. **系统：** RTOS 调度、任务、IPC、内存、状态机、并发、可靠性；
3. **接口：** GPIO、ADC、I²C、SPI、UART、RS485、CAN、Ethernet、Wi-Fi、BLE、MQTT；
4. **功能：** 采集、滤波、告警、控制、日志、配置、诊断、升级、恢复、产测。

每个知识点使用固定回答框架：

```text
原理是什么
→ 有哪些关键特性和参数
→ 在本项目怎样使用、为什么这样选
→ 常见故障是什么
→ 如何按软件、驱动、硬件、干扰顺序排查
```

题库只负责提出问题，答案优先由芯片数据手册、参考手册、协议标准和官方文档确认。

## 5. 调试原则

- 调试顺序采用：单功能调试 → 模块联调 → 系统联调 → 故障注入。
- 不要求把所有外设都实操，选择最能证明架构和排障能力的关键链路。
- 排查表达保持有条理：先应用状态和输入，再协议/驱动，再硬件连接与供电，最后考虑信号完整性、EMC和环境干扰。
- 每个重要实验记录：预期、步骤、关键日志/波形、异常、根因、修复和回归结果。
- “一次成功运行”不是充分证据，至少选择超时、断线、非法输入、断电/复位或重复请求中的一种失败路径。

## 6. 证据与简历表达

| 内部等级 | 证据 | 简历动词 |
|---|---|---|
| A 实机验证 | 开发板、代码、日志/波形、异常测试 | 实现、搭建、联调、验证 |
| B 台架/模拟验证 | USB-CAN、模拟节点、故障注入、替代硬件 | 搭建台架、模拟、验证策略 |
| C 设计研究 | 需求、框图、预算、状态机、伪代码、测试方案 | 设计、研究、评估、规划 |

理论研究可以成为项目亮点，但不能把“设计了”写成“量产部署了”，也不能把单板实验描述成通过工业认证。

## 7. 资料使用原则

- `暗室项目100道面试题.pdf` 和 `BMS项目100道真题.pdf` 用于建立问题索引，不视为权威答案。
- 器件能力、寄存器、接口、容量、时序和电气参数必须回到官方资料复核。
- 资料中出现与数据手册不一致、容量无法闭合或功能描述过度理想化时，将其转化为面试中的“质疑与取舍题”。
- 后续每一阶段只整理该阶段需要的问题，避免一次抄写 200 道答案。

## 8. 工作节奏

每次推进只完成一个明确产出，例如一张选型表、一份任务设计、一条关键流程或一组面试问题。阶段结束时更新项目上下文和证据等级，再进入下一阶段。
