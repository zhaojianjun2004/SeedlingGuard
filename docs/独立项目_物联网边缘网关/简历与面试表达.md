# 工业现场环境监测物联网边缘网关：简历与面试表达

> 技术方案与范围见 [项目方案](README.md)。本页只保留对外可读的项目故事和能够展开讲解的关键设计。

## 1. 简历项目条目

**工业现场环境监测物联网边缘网关**｜STM32F407ZGT6、ESP32-S3、FreeRTOS、RS485/Modbus RTU、UART、CAN、Wi-Fi、MQTT、HTTP

面向车间与机房等分散环境监测点，设计 F407 现场控制器与 ESP32 网络网关的双 MCU 架构，汇聚温湿度、光照等 Modbus 仪表数据，并向局域网页面和云平台提供实时状态、远程配置及故障诊断。

- 设计 F407 侧多从机 Modbus 轮询与数据质量处理，覆盖 CRC 校验、帧超时、设备级故障隔离和工程量转换；以版本号、长度、序号和 CRC 定义与 ESP32 的 UART 结构化帧，并通过板载 CAN2 与 USB-CAN 验证现场总线通信。
- 将网页和云端操作归一到同一命令链路，由 F407 校验并回传实际执行状态，再更新供 HTTP 页面轮询的状态快照与 MQTT 物模型，避免多入口状态不一致。
- 规划 ESP32 的 AP/STA 配网、NVS 参数保存、MQTT 重连及分级离线缓存；按 QoS 1 Broker 确认推进补传记录，区分链路接收、命令执行和云端确认。
- 设计关键任务进展门控看门狗、CAN Bus-Off 恢复与网络降级路径；ESP32 升级采用 A/B 试运行确认和失败回滚机制。

这四条足以形成完整叙事：**现场接入、跨板通信、统一控制、断网恢复**。简历版不加入没有设计清楚的吞吐量、连续运行天数、丢包率或功耗改善百分比。

## 2. 60 秒口述

“这个项目是面向普通工业环境监测点的边缘网关。现场有温湿度、光照等 RS485 仪表，F407 负责 Modbus 轮询、数据质量和实际采集状态；ESP32-S3 通过带 CRC 的 UART 帧接收结构化数据，再提供局域网页面和 MQTT 云端上报。F407 的 CAN2 另外通过 USB-CAN 与电脑联调。我重点处理了三个闭环：第一是采集值带质量和时间，不把超时后的旧值当新数据；第二是网页和云端走统一命令入口，由 F407 返回执行结果后再刷新状态；第三是断网缓存与补传，区分 UART 接收、MQTT 发布和 Broker 确认。网络模块故障时，F407 仍按最后有效配置继续采集。”

## 3. 面试追问速答

### Q1：为什么用两颗 MCU？

F407 管现场实时性、RS485 总线和实际状态；ESP32 管 Wi-Fi、TLS、MQTT、Web 与 OTA。两侧先通过带版本、长度、序号和 CRC 的 UART 帧交互，网络故障不会直接拖住现场采集。F407 的 CAN2 由 USB-CAN 验证；ESP32 侧缺收发器，所以当前不把 TWAI 算作板间实机链路。

### Q2：UART 连续字节流怎样识别一条完整测点消息？

帧头之后依次放版本、消息类型、16 位序号、长度、最多 32 字节载荷和 CRC16。接收器设长度上限，收齐后校验 CRC；错误时重新寻找帧头。测点载荷带测点 ID、质量、缩放值和样本年龄；接收端依据启动会话和序号去重，旧帧不覆盖新状态。F407 发给电脑的 CAN 诊断帧使用同一测点语义，但重新编码成 8 字节载荷。

### Q3：如何避免网页和云端同时下发命令打架？

入口先统一生成命令对象，包含来源、`request_id`、目标、参数和截止时间。F407 对同一控制对象串行处理、校验版本及范围，执行后回报实际状态。ESP32 只显示 F407 确认的结果；重复请求通过 ID/序号去重，超时保持“未知/待确认”，再查询状态。

### Q4：MQTT QoS 1 就能保证业务不丢不重吗？

不能。QoS 1 表示 Broker 至少收到一次，客户端可能重发；平台业务是否处理还需要业务回执或幂等键。网关将本地记录 ID 映射到 MQTT `message_id`，收到 PUBACK 相关事件后才推进本地待发状态；云侧按记录 ID 去重。

### Q5：Modbus 某个从机不响应怎么办？

单次事务设响应超时，超时或 CRC 错误只标记该设备的点位质量，不阻塞其他从机。连续失败达到阈值后降低它的轮询频率，留出恢复探测；旧值可显示，但保留原始采样时间并标记 `STALE/FAULT`。

### Q6：ESP32 掉线、F407 掉线分别怎样表现？

ESP32 掉线时 F407 继续采集并维持最后有效配置；网络恢复后 ESP32 补传它已保存的记录。两板 UART 超过心跳窗口无有效帧时，ESP32 将 F407 标记离线，页面和云端显示状态异常。F407 的 CAN2 若 Bus-Off，则记录错误计数并受控恢复，Modbus 采集与 UART 上报仍运行。

### Q7：F407ZGT6 的引脚和资源怎样分配？

先按霸天虎 V2 实际布线分配 CAN2 `PB12/PB13`、USART2/RS485 `PA2/PA3` 与方向脚 `PC0`、板载 SPI Flash 的 SPI1 `PB3/PB4/PB5` 和片选 `PG6`；板间 UART 暂选 USART3 `PD8/PD9`，这些脚与未安装的 LCD 接口复用。再用 CubeMX 检查复用、时钟与中断。

### Q8：为什么看门狗不能单独建高优先级任务定时喂？

喂狗任务正常运行不代表采集、CAN、存储都在前进。由监督器读取每个关键任务的进展计数、检查停滞与故障状态，条件满足才刷新 IWDG；故障发生后先保存最小诊断信息，复位后再做复杂持久化。

## 4. 保持项目叙事聚焦

- 主角是 **F407 现场接入 + ESP32 网络汇聚**，不是把 GitHub 的 F411 工程改一个芯片名。
- UART 是当前两板链路；F407 的 CAN2 与 USB-CAN/电脑联调；Modbus 接现场仪表，MQTT 与 HTTP 分别服务云端和局域网页面。
- 项目不加入 LVGL 触摸屏；局域网页面使用 HTTP 轮询状态。
- 面试时优先讲清数据帧、命令确认、缓存删除条件和故障恢复，避免用未经推导的性能数字代替设计逻辑。
